# 오작교 — 오늘을 짓는 다리

뮤즈테크의 어두운 화면, 초록색 포인트, 카드 탐색, 탭형 활동지, 학생·교사 화면 분리를 계승한 진로교육 웹플랫폼입니다. 첨부한 두 연구보고서를 바탕으로 구성했으며, 상세 활동 양식은 `편집본_20+20`의 부록 1~4, 10을 우선 반영했습니다.

## 바로 사용하기

별도 설치나 빌드가 필요 없는 HTML/CSS/JavaScript 프로젝트입니다. GitHub Pages 같은 정적 호스팅에서 실행합니다.

- 학생: `index.html`
- 교사: `teacher.html`
- 로컬 확인: 이 폴더에서 `python -m http.server 8000`을 실행하고 `http://localhost:8000`을 엽니다.
- 파일 더블클릭보다 위 HTTP 방식이나 GitHub Pages 사용을 권장합니다. 파일 주소의 저장소 동작은 브라우저에 따라 다를 수 있습니다.

## GitHub에 올리는 순서

1. ZIP을 풀고 `ojakgyo-platform` 폴더 안의 파일을 확인합니다.
2. GitHub에서 새 저장소를 만듭니다. 예시 이름: `ojakgyo-platform`.
3. **Add file → Upload files**에서 폴더 안의 파일과 `docs` 폴더를 올립니다. 저장소 최상위에 `index.html`이 보여야 합니다.
4. **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**를 고릅니다.
5. **main / (root)**를 선택하고 **Save**합니다.
6. 배포 완료 후 Pages 설정 화면에 표시되는 주소를 엽니다.
7. 학생 주소는 `https://계정명.github.io/저장소명/`, 교사 주소는 뒤에 `teacher.html`을 붙입니다.

공식 안내: [GitHub Pages 배포 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) (2026-10-02 확인).

기존 저장소의 하위 폴더에 추가할 때도 상대 경로를 사용하므로 동작합니다. `.nojekyll`은 선택 사항이며 Git으로 올리면 함께 포함됩니다. 웹 업로드에서 숨김 파일이 누락되어도 이 프로젝트는 일반 파일명만 사용하므로 페이지를 열 수 있습니다.

## 학생 사용 흐름

1. 교사와 정한 **고유 익명 코드**, 학년, 반을 입력하고 **코드로 기록 열기**를 누릅니다. 기본 `나의기록` 코드는 개인 체험용이므로 수업 제출 전 반드시 바꿉니다. 이름이나 학번을 공개할 필요가 없습니다.
2. 분야 둘러보기에서 관심 분야를 두 개까지 담습니다.
3. **새 활동**을 만들어 활동명·날짜와 `오` 기록을 작성합니다.
4. `작`에서 창직 설계 또는 학과·과목 설계를 고릅니다. 1학년도 교사의 안내에 따라 참여할 수 있습니다. 검사 결과를 자동 진단하거나 과목을 추천하는 서비스는 아닙니다.
5. `교`에서 멘토 질문과 들은 답을 남깁니다.
6. `다음 다리`에서 한 걸음, 실행 기한, 확인일, 실행 정도를 기록합니다.
7. **제출용 파일 내보내기**로 JSON 파일을 내려받아 교사가 정한 비공개 제출 경로로 보냅니다. 이 버튼 자체가 서버 제출은 아닙니다.
8. 포트폴리오에서 인쇄 또는 PDF 저장을 합니다.

입력은 현재 브라우저의 localStorage에 저장됩니다. 다른 브라우저·다른 기기에서 이어 쓰려면 내보낸 JSON 파일을 가져오세요. 학생 가져오기는 같은 코드의 기록을 파일 내용으로 교체하므로 먼저 현재 자료를 내보내세요.

공용 기기에서는 제출 파일을 보관한 뒤 **이 코드의 기기 기록 삭제**를 누르세요. 코드는 본인 인증이나 비밀번호가 아니므로 같은 기기를 사용하는 사람에게 기록을 숨겨 주지 않습니다.

## 교사 사용 흐름

1. 교사 전용 기기에서 `teacher.html`을 엽니다.
2. **학생 제출 파일 가져오기**에서 여러 JSON 파일을 선택합니다.
3. 같은 코드의 활동은 모아지고, 같은 활동 ID는 확인 후 가져온 파일로 갱신합니다. 파일을 가져오는 순서에 유의하세요. 최신 버전을 마지막에 가져오면 됩니다.
4. 학년·실행 정도·검색어로 기록을 찾고 **기록 보기**를 누릅니다.
5. 피드백과 상담 연결 여부, 다음 확인일을 저장합니다. **피드백 파일**은 별도로 학생에게 전달하는 TXT입니다. 학생 기록 가져오기 기능에는 넣지 않습니다.
6. CSV로 전체 현황을 내려받거나 교사 자료실을 JSON으로 백업합니다. 백업에는 학생 기록과 교사 피드백이 들어 있으며, 복원 시 현재 자료를 교체합니다.

실제 제출을 가져오기 전에는 집계가 0입니다. 연구보고서의 과거 만족도 수치를 현재 학생 데이터처럼 표시하지 않습니다. 통계는 활동 단위이며 한 학생의 여러 활동이 각각 집계됩니다.

## 포함 기능과 범위

| 기능 | 제공 방식 |
|---|---|
| 원본의 디자인 방향 | 다크 테마, 초록색 강조, 카드, 탭, 학생/교사 분리 |
| 멘토링 10개 분야 | 검색, 분야 필터, 상세 설명, 관심 2개 선택 |
| 공통 활동 기록 | 활동별 누적, 자기이해·발견·선택 근거 |
| 진로 설계 | 창직 설계 / 학과·과목 설계 |
| 멘토 질문 | 사전 질문 / 만남 후 생각 |
| 후속 실천 | 실행 기한, 확인일, 실행 정도, 자기점검 |
| 기록 저장 | 브라우저 저장, JSON 가져오기·내보내기 |
| 포트폴리오 | 활동 모음, 브라우저 인쇄/PDF |
| 교사 자료실 | 다중 제출 가져오기, 현황 CSV, 피드백, 백업 복원 |
| 계정 로그인·권한 분리 | 미포함 |
| 클라우드 자동 수집·기기 간 동기화 | 미포함 |
| 수업 개폐·제출 마감·영상 녹화 업로드·동료평가 | 미포함 |

첨부 뮤즈테크 ZIP의 README에 언급된 `Code.gs`, `Video.gs`는 실제 ZIP에 없었습니다. 기존 서버 URL과 OAuth 설정은 재사용하지 않았습니다. 원본과 화면 방향을 공유하는 **기기 저장형 진로교육 버전**이며 원본의 서버 기능까지 동일한 복제본은 아닙니다.

## 파일 수정 안내

- `data.js`: 분야 소개, 역량, 활동 문항. 질문 예시는 수업용으로 추가된 문구입니다.
- `index.html`, `teacher.html`: 학생·교사 화면.
- `platform.css`: 새 레이아웃과 반응형 스타일.
- `musetech-base.css`: 제공받은 뮤즈테크 공통 스타일.
- `app.js`: 학생 기록·탐색·포트폴리오.
- `teacher.js`: 교사 집계·피드백·백업.
- `shared.js`: 입력 검증, HTML 이스케이프, 파일 입출력.
- `docs/REPORT-MAPPING.md`: 보고서와 기능의 대응.
- `docs/VALIDATION.md`: 검증 내용과 수업 전 점검.

## 배포와 자료 보관

GitHub 저장소에는 이 프로젝트의 소스 파일만 올립니다. 학생 제출 JSON, 피드백, CSV, 보고서 원본, 학생 사진을 공개 저장소에 추가하지 마세요. 학생과 교사의 실제 기록은 소스 파일에 포함되지 않습니다. 교사 URL도 공개 페이지이며 로그인으로 보호되지 않습니다.

학급 간 자동 제출·구글 로그인 등을 운영하려면 별도의 인증과 데이터 저장 서버가 필요합니다. 그 단계에서는 서버에서 교사 권한을 검증하고, 학생은 본인 기록만 읽고 쓰도록 설계해야 합니다.

원본 소스와 보고서에 대한 이용 권한은 제공자의 권한을 따릅니다. 이 패키지는 별도 오픈소스 라이선스를 임의로 부여하지 않습니다.
