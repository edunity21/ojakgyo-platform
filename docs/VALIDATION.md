# 검증 기록

검증일: 2026-10-02

## 확인한 항목

- JavaScript 4개 파일의 Node 구문 검사 통과.
- 모의 DOM 환경에서 학생 활동 생성·삭제, 입력 저장, 코드별 기록 다시 열기, 3학년 설계 유형, 검색 필터를 확인.
- 학생 제출 형식 검증, 잘못된 버전·중복 활동 ID 거부, 입력 HTML 이스케이프 확인.
- 교사 제출 가져오기, 같은 활동 중복 가져오기 시 갱신, 피드백 저장, 전체 삭제 후 백업 복원 확인.
- HTML에서 참조한 로컬 스크립트·스타일 파일 존재 확인.

## 검증 한계

브라우저 자동화 실행은 현재 환경에서 `spawn EPERM`으로 차단되었습니다. 위 동작 확인은 모의 DOM 기반이며 실제 브라우저의 화면 렌더링·파일 다운로드·인쇄/PDF·모바일 터치 동작을 검증한 것은 아닙니다. GitHub에는 아직 업로드하거나 배포하지 않았습니다.

## 수업 전 브라우저 점검

1. 학생 화면을 열어 10개 카드가 보이는지, 모바일에서 가로 넘침이 없는지 확인합니다.
2. 테스트 코드로 새 활동을 만들고 입력 후 새로고침하여 기록을 확인합니다.
3. 관심 분야 두 개를 선택하고 세 번째 선택 시 안내가 나타나는지 확인합니다.
4. 제출 JSON을 내려받아 다른 브라우저의 학생 화면에서 가져옵니다.
5. 교사 화면에서 같은 파일을 가져오고 피드백을 저장한 뒤 다시 엽니다.
6. CSV, 교사 백업, 피드백 TXT 다운로드와 백업 복원을 확인합니다.
7. 포트폴리오 인쇄 미리보기에서 한글, 긴 문장, 여러 활동의 페이지 구분을 확인합니다.
8. 공용 기기의 기록 삭제와 테스트 파일 정리를 확인합니다.

저장 공간 부족, 브라우저 데이터 삭제, 시크릿 모드 종료로 기기 기록이 사라질 수 있으므로 수업 종료 시 파일 백업을 보관합니다. 학생 파일은 5MB, 교사 백업은 30MB까지 가져오며 학생 코드마다 최대 300개 활동을 지원합니다.
